`json` parses a JSON object and stores it under a name. Fields come back through the parameter, including nested ones through dotted paths. It pairs well with a parser that fetches a response body.

## For template authors

### Syntax

```yaml
{json(name):{"key": "value"}}
```

### Examples

```yaml
{json(user):{"name":"Parbez","age":30}}Your age is {user(age)}.
# Your age is 30.
```

Reach nested fields with a dot:

```yaml
{json(u):{"address":{"city":"Silchar"}}}You live in {u(address.city)}.
# You live in Silchar.
```

Any key starting with an underscore is refused and the tag is left as written:

```yaml
{u(_secret)}
# {u(_secret)}
```

## For developers

### Register the parser

<Tabs items={['ESM', 'CommonJS']}>
	```ts showLineNumbers tab="ESM"
	import { Interpreter, JSONVarParser, StrictVarsParser } from 'tagscript';
	const ts = new Interpreter(new JSONVarParser(), new StrictVarsParser());
	```
	```js showLineNumbers tab="CommonJS"
	const { Interpreter, JSONVarParser, StrictVarsParser } = require('tagscript');
	const ts = new Interpreter(new JSONVarParser(), new StrictVarsParser());
	```
</Tabs>

A [variable parser](/tagscript/parsers/variables) is needed to read the result back.

### Behaviour

Both the parameter and the payload are required. `parse` stores a [`SafeObjectTransformer`](/tagscript/transformers/object) on `ctx.response.variables` and returns an empty string.

<Callout type="warn">
	The payload is `JSON.parse`d. Invalid JSON throws, the interpreter catches it, and the render ends
	with the parser error as the body. Feed this tag output from a source you control, or wrap it in your
	own parser that validates first.
</Callout>
