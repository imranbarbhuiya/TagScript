`stop` ends the render as soon as its expression is true. The payload becomes the output and no tag after it runs. Use it to reject bad input before the rest of the template does any work.

## For template authors

### Syntax

```yaml
{stop(expression):message}
```

### Examples

```yaml
{stop({args}==):You must provide input.}Hello {args}
# when args is empty
You must provide input.
# when args is "Parbez"
Hello Parbez
```

### Aliases

`stop`, `halt`, `error`

## For developers

### Register the parser

<Tabs items={['ESM', 'CommonJS']}>
	```ts showLineNumbers tab="ESM"
	import { Interpreter, StopParser } from 'tagscript';
	const ts = new Interpreter(new StopParser());
	```
	```js showLineNumbers tab="CommonJS"
	const { Interpreter, StopParser } = require('tagscript');
	const ts = new Interpreter(new StopParser());
	```
</Tabs>

### Behaviour

The parameter is required. The payload is optional and defaults to an empty string.

`parse` throws a `StopSignal` carrying the payload. The interpreter catches it, abandons the remaining tags and returns the text rendered so far plus the message. Nothing propagates to your `await ts.run(...)` call, so you do not need a `try` block for this, and nothing is added to `response.errors`, because a stop is control flow rather than a failure.

`StopSignal` is exported, so your own parsers can end a render the same way:

```ts showLineNumbers
import { StopSignal } from 'tagscript';

if (overBudget) throw new StopSignal('That is enough for now.');
```

A stopped render still returns a normal `Response`. Anything earlier tags wrote to `response.actions` is still there, so check the actions you care about rather than assuming a stop means "do nothing".
